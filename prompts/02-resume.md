# 02 · 续接一个已有研究

> **用在哪**：换了 AI、上下文到了上限、或者隔了几天/几周回来。
> **核心原则**：**续接靠文件，不靠聊天记录。** 聊天记录不可检索，只存在于对话里的决定等于不存在。
> **前提**：项目仓库根目录里有 `PROTOCOL.md`、`AGENTS.md`、`prompts/`（开新研究时一并复制进去）。

```
你是接手，不是重开。这个研究之前在别的会话里做过。

项目仓库：<本地绝对路径>（AI 有文件访问时）
         或 <git 地址 / 网页链接>（AI 读不到本地时，见文末退化方案）

按顺序读，读完先汇报，先别问我"你想做什么"：
1. AGENTS.md —— 里面写了 PROTOCOL 该读哪几节（只读那几节，别全读）
2. RESEARCH_ACTIVE.md —— 确认活动分支
3. RESEARCH_ACTIVE 指向分支上的 PROJECT_STATE.md —— 当前问题、决策、未决
4. research/state.yml —— 阶段、活动轮次
5. 只读**最近一轮**的轮次文件；更早的历史不要读，需要时我让你查

汇报格式（缺哪项就说缺，不要编）：
状态：…
上次：…
未决：…
建议：…

汇报完，必须再做两件事，然后才往下走：
- 列出 PROJECT_STATE 里 RETIRED 的路线、RESEARCH_POOL §C 的否决项，
  向我确认「这些不再重提」
- 列出你觉得悬空的事项（讨论过但文件里没落盘的），问我哪些要补

禁止：
- 重述文件里已经写好的结论
- 重跑已经做过的实验
- 提出已经被否决的方向（先看 RETIRED 再说话）
- 因为"想帮忙"就自动开下一轮
```

## 为什么要那两条"必须做"

新 AI 最大的风险不是记不住，是**为了显得有用而重新开始**：重提已经否决的方案、重跑做过的实验、把结论再讲一遍。

- 「RETIRED 清单」挡住重提
- 「悬空事项」挡住丢失

## 退化方案：AI 读不到本地文件时

只贴三份，足够接上，不需要整个仓库：

1. `PROJECT_STATE.md`
2. `research/state.yml`
3. 最近一轮的 `ROUND.md`

再补一句：`上面三份是现状；先汇报四句，别急着建议。`

## 最坏的情况

如果文件里什么都没写（比如之前没按协议走），那就诚实说：

> 这个研究没有留下可供接续的结构化记录。我们从你现在记得的部分重建，
> 但请把这次重建的结果写进文件，否则下次还要再来一遍。
