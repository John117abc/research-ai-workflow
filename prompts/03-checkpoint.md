# 03 · 上下文快满时做一次保存

> **用在哪**：感觉聊到一半以上了，**别等它断掉**。
> **最重要的一条**：让它自己写「续接提示词」——你不用记格式，它替你生成。
> **最容易丢的东西**不是结论（结论通常写下来了），是**「为什么排除某条路」**。所以第 1 条必须含理由。

```
我们这轮快到上限了。先做一次保存，再继续。

把这次会话里**还没写进文件**的东西落盘：

1. 新决定 → PROJECT_STATE 决策记录（日期 + 理由，**理由不能省**）
2. 新的未决问题 → PROJECT_STATE 未决表 或 RESEARCH_POOL
3. 新产生的 claim → papers/<id>.md 或 RESEARCH_POOL §B
4. 本轮进展 → 当前 ROUND.md 的执行记录
5. 下一步第一件事 → ROUND 的「下一轮候选」或 state.yml

落盘时注意：
- 只写这次真的发生过的；不要为了好看补充没做过的动作
- 拿不准是「已核实事实」还是「报告声称」的，一律降到「报告声称」
- 被否决的方向若还没记，补进 RETIRED 并写「什么新证据才允许重开」

写完，再给我一段「续接提示词」：
包含仓库路径、当前轮次、下一步第一件事，
格式要能让我直接粘贴给下一个 AI。
```

## 保存完要检查什么

- [ ] `PROJECT_STATE.md` 的决策记录多了至少一行，且**有理由**
- [ ] `state.yml` 的 `phase` / `round` 与实际一致
- [ ] 当前 `ROUND.md` 的执行记录不是空的
- [ ] 拿到了一段可以直接粘贴的续接提示词

## 如果已经断了

不要试图在旧会话里找回。直接开新会话，用 `02-resume.md`。

代价是失去"最后一次未落盘的讨论"——这是可以接受的损失，前提是你现在就把这次教训记住：**下次在感觉过半时就保存**。
