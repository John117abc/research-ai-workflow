# 科研 AI 协作约束（v2.1 模板）

> 位于活动研究分支。规则约束 AI 执行，不规定本学科的科学结论。

## 任务启动门

- 先读根目录 `PROTOCOL.md`（AI 执行手册 v2.1；不在就问研究者要，不要凭记忆执行）。
  **只读 §0 三条铁律、§1 开工检查、§11 一页速查**（约一页）；其余小节按需加载，不要一次读完全文。
- 再读 `RESEARCH_ACTIVE.md`（默认分支）、本分支 `PROJECT_STATE.md`、本文件、当前获批准的 `research/rounds/R00X.md`。
- 核对 Git 当前分支、HEAD、工作区，以及目标项目/论文。与指令不一致时停止并报告，不自行切换分支、覆盖本地改动或改写状态文件。
- 无明确批准任务：只能讨论、只读检查和拟定方案；不改代码、不跑新实验。

## 权限分级

| 分类 | 可做什么 | 边界 |
|---|---|---|
| A 普通工程事项 | 已授权任务范围内的日志、格式、非语义重构、可复现性测试、bug 修复 | 记录 diff 与测试；若影响行为或科研结论，升级 B |
| B 科学方法改变 | 只可拟定变更申请 | 必须提交**旧方法/新方法/必要性/预期影响/验证方式**，等研究者明确批准；批准前不执行 |
| C 科学方向改变 | 只可提出替代研究问题或新的项目建议 | 研究者明确决定前，保持当前主线及非目标不变 |

B 包括但不限于：新算法/证书、任务或可行性约束、场景或数据筛选、指标、基线、阈值、假设、时间范围、完成条件。无既往审批记录应写 `UNKNOWN`，**Git 提交/AI 自述不等于审批**。

## 执行与停止

- 严格使用轮次文件规定的允许文件、命令、预算、数据与输出。不得以“提升效果”为理由擅自扩展。
- 新论文或新思路先进入项目 `RESEARCH_POOL.md` 的待讨论项；如有独立 `research-library`，按需引用其条目。不得仅因导入文献就启动新实验。
- 碰到阻断性科学问题：保留原始证据，列出审批申请，停止受影响的操作；非阻断问题记待办，不开启连续全面审计。
- 达到验收条件后停止。除非明确授权，不提交、不推送、不启动下一轮。

## 验收交接

- 核实事实、执行报告声称、推断、UNKNOWN 分开写；给出文件路径、commit、输入数据和测试记录，不能虚构。
- 测试写明通过/失败/跳过的数量；不把 skip 当 pass；明确 dirty 工作树、未提交归档、环境依赖。
- 算法变更的解释包含旧/新机制、动机、简化例子、影响边界和反例。研究者能理解才可进入科学结论讨论。
- 交接默认短摘要、表格和证据链接；未验收不能将轮次标记 `CLOSED`。

## 文献来源边界（v1.1）

- Zotero 为题录/PDF/原始笔记主库；只有用户明确授权，才可读取用户指定的导出目录。不得直接写入或清理 Zotero 数据库。
- Zotero 元数据、导出的原始笔记、AI 生成的结构化摘要应明确区分；不凭题录、摘要或 AI 摘要捏造页码/实验结论。
- 论文库读写不得绕过本项目 `ROUND.md` 的文件与科学方法修改权限。
