# research-flow 科研流程规格 v0.3

> 一句话：**让 AI 参与科研全流程，但决定权始终在研究者手上。**
> 载体：Git 仓库（规则、状态、证据）；AI 是执行者；插件是可选外挂，只补三根钉子。
> 本文是流程规格，不是软件设计。**它不需要任何程序就能手工执行**——这是它成立的前提。

---

## 1. 核心对象：claim（主张）

整条流程只搬运一种东西：**一条主张**。它从论文里被提取，变成待检验问题，变成实验，变成结论，最后变成决策。

```
C-007
  陈述   anchor 先验未覆盖的意图，在有限采样预算下可能被遗漏
  来源   zou_diffusiondrivev2_2025 · 摘要 · 位置未核对
  条件   固定预算、NAVSIM、ResNet-34 骨干
  状态   SOURCED
  谱系   → I003（探索点）→ R4（轮次）→ REFUTED（结论）
```

**六档状态**（取代分散在四个文件里的四套词表）：

| 状态 | 含义 | 落在哪 |
|---|---|---|
| `SOURCED` | 来自论文，有位置；分「摘要级 / 已核对」两档 | `papers/<id>.md` |
| `OPEN` | 被采纳为待检验问题，有可证伪条件 | `RESEARCH_POOL` §B |
| `UNDER_TEST` | 有已批准的轮次在检验 | `research/rounds/RN.md` |
| `SUPPORTED` / `REFUTED` | 实验有结论，附证据等级 | `PROJECT_STATE` 证据表 |
| `RETIRED` | 放弃，必须写原因与重开条件 | `RESEARCH_POOL` §C |

**为什么必须是 claim 而不是"论文"**：读几篇之后找探索点，输入不是某篇论文，是**几篇的主张放在一起比**。字段不同构就只能写含糊归纳——这正是现在 `LITERATURE_BASELINE.md` §2 通篇标「初步判断，待原文核对」的原因。

## 2. 主循环与三个回流口

```
① 带着问题读几篇论文
② 和 AI 讨论细节
③ AI 入库（摘要层）+ 你提取 claim（证据层）
④ 跨论文合成 → 候选探索点
⑤ 收敛成一个可证伪问题
⑥ 冻结实验（含消融设计）
⑦ 执行（按仓库提示词）
⑧ 裁决 → 结论
⑨ 归档 + 下一条 claim
```

这不是流水线。三个回流口会把流程拉回前面：

- **卡住时** → 回看库：「谁主张过、什么条件、有何反例」
- **发现缺口时** → 补文献：看主流其它论文，作为库外输入
- **证据不符预期时** → 修订主张：改条件或改陈述，**不偷偷改结论**

## 3. 读论文：分诊 → 读前 → 读中 → 读后

### 3.1 分诊（入库时强制）

三问，任一为「是」才进精读队列：

1. 它是当前假设的最强竞争或最直接基线吗？
2. 我要复现或改造它的方法吗？
3. 它有可能推翻我的假设吗？

三问全否 → 只做粗读或 AI 总结，并**在库里显式标注强度**。

### 3.2 读前

AI 给 **N 条留意方向，每条挂 1 个张力型问题**。N 不固定，由这篇论文与当前研究问题的相关性决定，取值范围 1–5；AI 必须说明「为什么是 N 条」，否则默认 1 条。

问题只针对张力，不针对结论：

- ✗ 「作者用了什么损失函数？」——找答案型，读完就知道，对理解无帮助
- ✓ 「它为了效率牺牲了什么，这个牺牲在我的场景里能接受吗？」——张力型，必须边读边想

方向与问题都不给答案、不剧透结论。

### 3.3 读中

采集 Zotero 批注（高亮 + 短评）。**可选，不阻塞流程**。

现状：研究者从未导出过批注，但库里有批注痕迹（`topics/*.md`「研究者 Zotero 批注：…」）——数据在、通道没建。所以：

- 通道一次性建好（批量导出，或 Zotero 本地 API，见 §10），之后零手工
- 通道未建成时，本步留空，流程靠读后推进
- 批注是**旁证**：它比自我评估更能暴露理解缺口

### 3.4 读后①：无提示复述（3 问）

合上论文，不看笔记：它把什么换成了什么？核心机制一句话？最强证据是什么、支撑到什么程度？

### 3.5 读后②：精读八问（固定骨架）

1. 它替换/改进了什么（旧法 → 新法，具体到机制）
2. 核心机制一句话 + 关键公式/定义的位置
3. 最强基线是谁，比较是否同口径（数据/指标/预算）
4. 关键结论的证据位置（表/图/节/页），支撑到什么程度
5. 成立条件：数据、场景、假设、参数范围
6. 失败场景或作者承认的局限
7. **探索期**：它给了我什么新问题 ／ **检验期**：它挑战我哪条假设（写 ID）
8. 我最想验证或反驳的一点 → 写成下一个可证伪问题

八问的产出即 claim，只是尚未核对。

### 3.6 核对：四类判定

| 判定 | 含义 | 后续 |
|---|---|---|
| `MATCH` | 与原文一致 | 记录位置，可作证据 |
| `DEVIATION` | 有出入 | 给原文表述，记入理解缺口 |
| `BEYOND_TEXT` | 你有道理但原文没这么说 | **你的新见解**，转 `IDEAS`，不得当作者结论 |
| `NOT_ANSWERED` | 未答出 / 缺位置 | 记缺口；本论文不得升「已核对」 |

### 3.7 入库：两层必须分开

| 层 | 内容 | 谁产生 | 检索时 |
|---|---|---|---|
| **背景层** | AI 摘要、题录信息 | AI | 默认不返回 |
| **证据层** | claim + 位置 + 条件 + 缺口 | 研究者核对过 | 默认只返回这层 |

**这条是硬规则**：AI 摘要永远不能进「最强基线」的论证。否则半年后库变成一堆看起来都读过的摘要，而你无法分辨哪条能拿去支撑结论——那比现在更糟，因为现在你至少知道它是摘要。

### 3.8 存量论文：回忆式 claim 化

已读过但无记录的论文，**不重读**：凭记忆答八问 → 只核对答过的部分 → 缺口清单。约 10 分钟/篇，对比重读的 30–40 分钟。

副产品比主产品值钱：`DEVIATION` 多的才需要重读；`MATCH` 多的只说明掌握了但没留档。

阅读状态三档：`UNASSIGNED`（没读）／`READ_UNRECORDED`（读过无记录）／`DEEP_REVIEWED`（有 claim、有位置、有缺口清单）。缺中间档会导致重复读，或把「我读过」当成「我有依据」。

## 4. 跨论文合成：找探索点

输入：若干条 `SOURCED` claim。输出：候选探索点（`OPEN`）。

做法：按主张而非按论文并列，比较三件事——**共同主张、相互冲突、都没回答的空白**。每条候选必须带：

- 它否定了谁的什么主张（或补了什么空白）
- 最小反证思路：什么结果会让它立刻死掉
- 依据的 citekey 列表

无「最小反证」的候选，不许进 `OPEN`。

## 5. 冻结：实验计划

冻结时**必须同时写消融**，不能留到事后。

理由：消融事后补会退化成事后解释（跑完发现 A 有效，再补个「去掉 A 变差」来证明 A 有用）。这在方法学上是 HARKing，审稿人一眼能看出来。

轮次文件需含机器可读的授权块（否则无法判断越权）：

```yaml
---
round: R4
status: APPROVED
allowed_files: ["experiments/paper1/**", "research/rounds/R4.md"]
read_only: ["data/**"]
forbidden: ["src/certificates/**"]
budget: { runs: 3, gpu_hours: 4 }
ablation:                      # 冻结时就要有
  - { id: A1, remove: "anchor 间截断 GRPO", expect: "跨 anchor 优势比较失效" }
approved_by: researcher
approved_at: "2026-11-04T21:10+08:00"
approval_quote: "同意这轮只做覆盖度量，不动证书"
---
```

批准记录只能是研究者原话 + 时间 + 出处。Git 提交、AI 自述、测试通过都不算。

## 6. 执行与裁决

### 6.1 防失控：三种失控，三种对策

"科研失控"不是一个问题，是四个：

| 失控的表现 | 真正缺的 | 对策 |
|---|---|---|
| 不知道 AI 改了哪 | 文件级记录 | git diff + 白名单（可自动） |
| 不知道改的后果 | 影响面陈述 | 变更预告必填「后果」 |
| 不知道它现在在干什么 | 实时进度 | 动手前/后各一句话 |
| 解释看不懂 | 降维 + 校验 | 分层解释 + 理解校验 |

前三项是**可审计性**，第四项是**可理解性**。加门禁只能解决前三项，第四项必须换机制。

### 6.2 变更预告（沿用现有 A/B/C 分级）

- **A 级**（日志、格式、非语义重构）：只记录，不预告
- **B 级**（影响科学结论）：必须先预告，等批准
- **C 级**（科学方向）：停下讨论，不动手

B 级预告固定五格，加一句**人话**：

```
【变更预告】R4-07
改哪里   experiments/paper1/05_recertify_static.py
改什么   给现有函数加一个可选参数，输出证书完整字段
为什么   现在只存摘要，R2 无法复现
后果     生效：导出文件约大 3 倍；已有结论不变；需重跑一次 03 脚本
         失败：回退一个 commit，无副作用
怎么验   跑消融 A1，看 CERTIFIED 条目数是否不变
人话     「原来只记结论，现在把推导过程也存下来，已有数字都不受影响」
等你     你回「批准」我才动手
```

**「人话」是强制项**：不含术语，用最普通的词说清「这对研究意味着什么」。写不出人话，说明 AI 自己没想清——那就该停下来想，而不是先动手。

### 6.3 后果预测替代机制理解（最关键的一条）

有些改动你**永远读不懂**，不是解释不够简单，是它超出了你现在需要理解的层次。这时候控制感不该来自「我读懂了代码」，而该来自「我能预测它的后果」：

- 如果这个改动是对的，哪个数字应该变？往哪个方向变？
- 如果跑完发现它没变，说明什么？
- 如果变了但方向相反，先怀疑什么？

**能预测，就能验收。** 这比读懂实现便宜得多，而且对超出认知的部分，它是唯一可行的控制方式。

所以每次 B 级改动必须写一行「预期可观察后果」，并在裁决时与实际结果对照。**没写预测的改动，等于无法验收**——不管代码看起来多对。

### 6.4 理解校验（只在 B 级触发，每次一次）

不是问「你懂了吗」，是让你用自己的话回答一句：

> **这个改动会让哪个结论或数字发生变化？**

- 答对 → 批准有效，动手
- 答不出 → AI 换一种说法重讲，或**把改动拆小到你能预测**
- 拆不小 → 说明这次改动太大，应该拆成两轮

这是唯一能真正防「看不懂」的机制。代价是你每次花 30 秒，所以只在 B 级做，A 级不做。

### 6.5 实验台状态

「不知道 AI 现在真正在干什么」，缺的是一句实时状态。固定四要素：

**动手前**：目标 / 预计改哪个文件 / 预计产出 / 预计耗时
**动手后**：实际 vs 预告（有无偏离）/ 结果 / 下一步

卡住、偏航、需要改变范围时，立即说，不等做完。

### 6.6 裁决

证据分四类，不可混用：**已核实事实／报告声称／推断假设／UNKNOWN**。测试分别写 passed / failed / skipped，skip 不算通过。

交接必须同时给出「预期 vs 实际」对照。预测对了，控制感才建立；预测错了，那是**最有价值的信号**——说明你对系统的理解有偏差，比结果本身更值得记下来。

### 6.7 累积失控：归因优先于变量数

失控很少是单次越权造成的，更多是**累积**：十几处改动，每处都单独解释过，合起来成了黑箱。效果不好时无法归因，只能一步步问 AI。

四个机制：

| 机制 | 做法 | 防止 |
|---|---|---|
| **改动台账** | 每行：ID／加了什么／期望／跑了什么／结果／保留或撤销 | 忘记改过什么 |
| **可独立开关** | 每个 B 级改动必须是 flag 或 config，能单独关掉 | 无法归因 |
| **常驻基线** | 保留「上一个已验证版本」的 commit + config，随时可回 | 不知道改坏了什么 |
| **轮次性质** | 冻结时声明 `EXPLORATORY` / `CONFIRMATORY`；探索轮不限变量 | 事后把多变量结果说成因果 |

**归因顺序**（效果不好时，别先问「为什么」）：

1. **跑回归**：已知结论有没有被打破？打破了 → 区间已缩到某几个改动
2. **二分**：关掉后半数改动重跑，继续缩小
3. **查数据与配置**：口径是否变了——最常见，也最容易被忽略
4. 最后才谈机制

第 1、2 步**你自己就能做**，不需要问 AI。前提只有一个：改动可开关、台账在。

**不限制变量数，限制结论强度**（这条取代原来的「每轮 ≤2 变量」）：

| 变量数 | 轮次性质 | 允许的结论 | 证据等级上限 |
|---|---|---|---|
| 1–2 | `CONFIRMATORY` | 「A 有效」——可归因 | 已核实事实 |
| 3+ | `EXPLORATORY` | 「这个组合达到 X 分」——**不得声称因果** | 报告声称 |

规则：

- 性质在**冻结时声明**，不能跑完再改口。否则结果是好的就说"这是确证轮"，是坏的就说"我本来只是探索"——这是 HARKing 的入口。
- 探索轮可以随便加变量，快、自由、允许失败。但它产出的是**假设**，不是结论。
- 探索轮之后必须跟一个确证轮：把变量拆开，单个验证。**探索找方向，确证定结论。**
- 探索轮的结果不得写进论文主张，也不得用来关闭母轮次。

这样既不用逼你守纪律，又保住了归因：**你可以乱试，但不能从乱试里编因果。**

**为什么这次不是「靠你记得」**：台账是文件，二分是机械操作。两者都不依赖任何人的记性，也不依赖 AI 在场。

### 6.8 代码不可读时的控制面

**前提**：实验代码主要由 AI 写，研究者不会逐行读，将来更不会。所以「读代码」不能作为控制手段——这条路必须承认关死了。

控制点转移到两处：**接口**和**证据**。

**（1）控制面板：每个科学改动必须是一个命名开关**

| 字段 | 例 |
|---|---|
| flag 名 | `--use_anchor_grpo` |
| 一句话作用 | 「同一 anchor 内的样本之间做优势估计」 |
| 默认值 | `off`（关闭 = 上一版行为） |
| 预期影响方向 | 训练稳定性↑，闭环分数可能↓ |
| 对应消融 ID | `A1` |

规则：开关必须能单独关掉，关掉即回到上一版行为。**禁止隐藏开关**——写死在代码里的科学改动，等同于越权修改。

**（2）你每轮只审三样，约 5 分钟**

1. 变更预告（人话 + 后果）
2. 开关清单 diff（新增了哪些旋钮，旧的默认值变没变）
3. 回归结果（已知结论有没有被打破）

审**接口**而不是审**实现**。就像开车不需要懂发动机，但要知道每个按钮管什么。

**（3）例外：评估与数据管线不能放弃审查**

理由很简单：**模型写错了只是没效果，评估写错了会得出错误结论。** 后者是科研事故，前者只是浪费算力。

所以评估、指标实现、数据切分这三处要求**已知答案测试**：人工构造一个小例子，正确答案能手算出来；如果 AI 写的评估代码在这个例子上算错，它很可能在主实验上也算错。

**（4）抽查纪律**：每轮只抽查一处，优先级是 评估 > 数据切分 > 配置 > 模型。

### 6.9 用官方库：风险从「算错」变成「接错」

评估实现交给 benchmark 官方库，"指标算错"的风险降到最低。但风险不会消失，只是转移了——而且更隐蔽，因为接错**不会报错**。

| 接错的方式 | 表现 |
|---|---|
| split 泄露 | 数字虚高，换环境复现不出来 |
| 配置不对齐 | 与官方 baseline 不可比（采样数、集成方式、后处理不同） |
| 后处理不一致 | 同一个模型，分数差几个点 |
| 库版本漂移 | 三个月后数字对不上，无法解释 |

**最有效的一招：每个新 benchmark 的第一轮，必须是复现官方 baseline 的公开数字。**

复现不出来 → 口径有问题 → 此时任何「改进」数字都不可信。**先修口径，不要跑改进实验。** 这一步花一天，能省掉后面三个月的不确定性。

**强制记录四项**（写进轮次文件）：

- 库版本 + commit（`pip install` 会漂移，必须锁）
- split 声明：train / val / test 分别是哪些
- 与官方 baseline 配置的逐项 diff
- 后处理步骤（轨迹选择、平滑、NMS 等）

**抽查优先级随之调整**：数据加载（split）> 后处理 > 配置 > 训练循环。

理由：用官方库之后，你真正在写的只有"胶水"——加载、配置、循环、后处理。**出错几乎都在胶水里，不在算法里。**

## 7. 对话准则（苏格拉底式，只在关键节点触发）

日常讨论不触发，保持顺畅。四个节点必触发：

| 节点 | 挑战什么 |
|---|---|
| 探索点要写成可证伪假设**之前** | 这个问题本身值不值得问 |
| 批准实验**之前** | 基线够不够强、预算够不够、**消融缺不缺** |
| 一轮结束要下结论**时** | 证据是否真的支撑这个结论 |
| 写进论文/对外表述**之前** | 措辞是否超出证据 |

**触发时必须做到：**

1. 先复述研究者的主张，等确认（避免打稻草人）
2. 给出**最强的那个反对**，不是「但是也可能存在…」
3. 说明这个反对要成立需要什么证据
4. 给出至少一个研究者没提到的替代解释
5. 最后给一个能证伪的问题，而不是一句总结

**禁止：**

- 以「你说得对」「这是一个很好的想法」开头
- 同时列支持和反对却不表明哪个更强
- 有明显漏洞时只说「可以考虑进一步…」
- 连续多轮只顺着研究者的方向补充细节

**另外两条：**

- 每轮最多推进一个结论；一轮产出三个待验证主张等于什么都没推进
- **发现方向走不通时，AI 必须明确说「建议停止」并给出理由，但不代为终止**——决定权在研究者

## 8. 权责表：AI 管广度，人管取舍

| 决定 | AI | 研究者 |
|---|---|---|
| 读哪些论文 | 推荐、指出缺口 | **选** |
| 论文说了什么 | 提取 + 标位置 | 核对 |
| 有哪些可探索点 | 提候选、给反例 | **选** |
| 假设怎么写 | 起草 | **定稿**（必须能证伪） |
| 指标/基线/预算 | 提建议、报风险 | **批准** |
| 代码与实验 | 执行、留证据 | 审 |
| 结果说明什么 | 分证据等级 | **裁决** |
| 要不要继续 | 提示缺口、建议停止 | **决定** |
| 论文措辞 | 起草 | **定** |

加粗项不可让渡。这不是「全流程代劳」，是「全流程参与」。

## 9. 门禁：九道，挂在六步上

| 编号 | 挂在 | 卡什么 |
|---|---|---|
| G1 | 提取 | 无证据位置 → 不许标「已核对」 |
| G2 | 采纳 | 无可证伪条件 → 不许进 `OPEN` |
| G3 | 冻结 | 无研究者批准记录 → 不许 `UNDER_TEST` |
| G4 | 执行 | 改动超出白名单／无消融设计 → 停 |
| G5 | 裁决 | 缺证据等级、skip 当 pass → 不许下结论 |
| G6 | 裁决 | 没写「预期可观察后果」→ 不许下结论 |
| G7 | 冻结 | 未声明轮次性质（`EXPLORATORY`/`CONFIRMATORY`），或上轮未做归因 → 不许冻结 |
| G8 | 执行 | 新增科学行为没有对应命名开关 → 视为隐藏改动，拒绝 |
| G9 | 裁决 | 探索轮的结论被写成因果，或证据等级越级 → 拒绝 |

**门禁只在冻结之后变硬**。探索期只跑 G2（可证伪性），其余放行——探索被流程打断的代价，远大于它防住的风险。

## 10. 载体

| 层 | 载体 | 判据 |
|---|---|---|
| 规则与模板 | `research-ai-workflow` 仓库 | 稳定、可迁移 |
| 知识 | `research-library` 仓库 | 同上 |
| 项目状态与证据 | 各研究项目仓库 | 同上 |
| 执行者 | 任何 AI ＋ 研究者 | 不绑平台 |
| **门禁** | 手工 → 可选插件 | 机器执行 |
| **视图** | 手工 → 可选插件 | 机器生成 |

**插件不是必需的**。它只补三根钉子：**记录**（把对话落到固定字段）、**拦截**（无批准不许动手）、**视图**（把四份文件合成一句「我在哪、缺什么」）。

三根钉子之外的东西都不该做进插件——出方向、判断新意、决定取舍，本来就不该自动化。

**Zotero 批注通道**（§3.3 的前置）：不得直连 Zotero SQLite（`research-library-starter/AGENTS.md` 第 1 条）。可选路线：批量导出 Markdown（零依赖、需手动一次）／Zotero 本地 API `127.0.0.1:23119`（零手工、需常驻）。

## 11. 好用度：以步骤数当验收标准

载体的摩擦会直接吃掉研究产出——16 篇读过没留记录，不是懒，是「记一次」要跨三个文件。

| 动作 | 现在 | 目标 |
|---|---|---|
| 回看一次库 | 开 baseline → 找主题 → 翻 2–3 篇 → 自己合并 | 1 次提问，返回 ≤5 条带位置的 claim |
| 采纳一篇论文进 pool | 列清单 → 等批准 → 改（≥3 步） | 批准即写入 |
| 精读后落库 | 手写段落 + 手改总表 | 答题即生成 |
| 开新一轮 | 复制模板 → 填 5 节 → 写批准记录 | 说清目标，其余自动填 |

人只对量级变化有反应，对百分比没反应。**降一半没用，降到 1–2 步才算。**

## 12. 不做什么

- 不做向量检索／RAG／自动读 PDF／写 Zotero 数据库
- 不自动判断创新性、不代替研究者决策
- 不做多人协作、云同步、Web 端
- 未经明确授权不提交、不推送
