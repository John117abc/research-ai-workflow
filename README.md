# 科研 AI 协作流程 v2.0

> 适用于「研究者 + AI + Git」的科研协作仓库。**不是自动化平台**，是一份可手工执行的协议。
>
> v2.0 相比 v1.1：方法论不变，**补上了「怎么做」这一层**——AI 每次开工读什么、每步输出什么格式、什么情况必须停。

## 三层文件，读哪个

| 文件 | 给谁 | 什么时候读 |
|---|---|---|
| [`PROTOCOL.md`](PROTOCOL.md) | **AI** | 每次开工第一件事 |
| [`docs/DESIGN.md`](docs/DESIGN.md) | 人 | 想知道某条规则为什么这么定 |
| [`docs/METHODOLOGY-v1.1.md`](docs/METHODOLOGY-v1.1.md) | 人 | 想理解整体思路与研究生命周期 |

## 三句话

1. **AI 管广度，人管取舍。** AI 负责找全、找反例、报风险；选方向、定假设、批口径、下结论由研究者做。
2. **好规则约束记录，不约束行为。** 硬限制「每轮最多加两个变量」会被绕过；改成「探索轮只能说达到几分，不能说因为谁」，就能活。
3. **没有证据位置的主张，不许写成「已核对」。**

## 快速开始

**开新研究**：让 AI 按 [`PROTOCOL.md`](PROTOCOL.md) §10「开新研究」初始化整个仓库——它先跟你确认仓库拓扑（一个仓库还是两个），再建目录、填三个文件，最后空手跑一次 §1 来验收。

**已有研究**：把 `PROTOCOL.md` 放进仓库根目录，让 AI 从 §1「开工检查」开始，先汇报，再动。

## 目录

```text
├── PROTOCOL.md        AI 执行手册：开工读序、七环节输出格式、九道门禁、四个挑战节点
├── docs/
│   ├── DESIGN.md      设计规格：claim 模型、主循环、防失控、载体与好用度判据
│   └── METHODOLOGY-v1.1.md   方法论：五阶段生命周期、A/B/C 权限分级、五格审批
├── templates/
│   ├── RESEARCH_ACTIVE.md    默认分支：指向当前活动研究
│   ├── AGENTS.md             活动分支：AI 权限边界
│   ├── PROJECT_STATE.md      活动分支：科学问题/决策/证据
│   ├── RESEARCH_POOL.md      活动分支：本项目文献索引与想法
│   ├── ROUND.md              每轮一份，含机器可读授权块
│   └── state.yml             当前阶段与活动轮次（可选，手工维护）
└── examples/
    └── MOSAIC_R1_R2.md       真实案例及证据限制
```

## v2.0 改了什么

| 变更 | 原因 |
|---|---|
| 新增 `PROTOCOL.md` | v1.1 只有原则，AI 每轮自由发挥；协议把输出格式固定下来 |
| `ROUND.md` 增加 front-matter 授权块 | 越权检查需要机读的文件白名单，中文表格读不了 |
| 新增 `state.yml` 模板 | 四套状态词表（阶段/轮次/想法/证据）需要一个汇总入口 |
| 方法论移入 `docs/` | 根目录留给「每次都要读」的入口 |
| 新增「防失控」规则 | 见 `docs/DESIGN.md` §6：变更预告、预期后果、理解校验、改动台账、先复现 baseline |

方法论（五阶段、A/B/C 分级、五格审批、证据四类）**一条都没改**。

**v2.1 小幅增补**：`PROTOCOL.md` 自带加载策略（只读 §0/§1/§11，其余按需）与 §12 维护约定（主仓库唯一权威、项目副本只读）。加载策略同时写进 `templates/AGENTS.md`——因为它必须在「读手册之前」就被知道。

## 边界

不解决：自动证明数学结论、保证创新性、代替研究者决策、自动验证 AI 是否真的执行过本地命令。

重要结论仍需证据与独立复核。**自动化的只是记录、拦截和视图，不是判断。**
